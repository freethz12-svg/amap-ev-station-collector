# 高德汽车充电场站采集操作手册

## 1. 任务边界

输入是包含目标名称的 Excel。保留目标原名和顺序。对每个目标只处理高德 Web 服务 API 返回的 **3 公里范围内**候选场站。输出只包含对外营业的汽车充电场站，不分析蔚来场站。

采集字段固定为：目标名称、场站名称、运营商、距离、充电功率(kW)、枪数量、开始时间、结束时间、总价、电费、服务费。不得增加停车费、营业时间、评分、地址、活动、空闲枪数等业务字段；营业时间和地址只能作为筛选/核对证据，不进入最终业务表。

## 2. 阶段 A：API 建候选名单

### 2.1 启动检查

1. 读取输入 Excel，输出目标总数和逐项原名。
2. 使用高德 **Web 服务 Key** 调用地理编码/POI 周边搜索。Android Key 用于 SDK/应用签名场景，不用于服务端 Web API。
3. 对每个目标先取得可靠坐标；名称歧义时结合城市、区县和返回地址核对。不得悄悄改写输入名称。
4. 周边检索半径固定为 `3000` 米。分页拉取直至 API 无新记录；不要只取第一页。
5. 保存原始 JSON，至少保留目标名、目标坐标、POI ID、POI 名称、类型、地址、经纬度和 API 距离。

### 2.2 候选筛选

先用名称、类型、地址和高德类别做自动筛选，再对边界项人工/APP 复核。删除：

- 蔚来、NIO、蔚来能源及蔚来自营/超充/换电点；
- 卡车专用、重卡专用、物流车内部专用且不面向普通汽车的站点；
- 电瓶车、电动自行车、两轮车充电/换电、车行、维修店、电池店，例如仅体现“台铃车行”等；
- 小区、企业、园区、酒店、机关等明确写明内部、员工、业主、专用、不对外的点位；
- 只有品牌或泛称、无法定位的名称，例如单独“星星充电”“电动汽车充电站”且无地点后缀、地址特征或可靠 POI ID；
- 不是充电场站的经销店、汽车销售/维修、停车场普通 POI、广告点；
- 在高德 APP 详情页没有营业信息、没有可识别场站详情结构的点位。

“名称可疑”不等于自动保留。必须能让手机端用名称/POI ID稳定找到具体站点。对无法明确判断的候选记录排除原因，不猜。

### 2.3 两份名单

生成：

- **按目标及距离名单**：一个场站可在不同目标下重复，用于回填每个目标的距离；
- **去重采集名单**：优先以 POI ID 去重；无 POI ID 时用规范化场站名 + 地址 + 坐标近似去重。保留其对应的全部 `target_distances`，手机只采一次，最后反填到多个目标。

不要仅按名称去重；同名不同地址/坐标可能是不同站。

## 3. 阶段 B：ADB 与 APP 证据采集

### 3.1 设备连接

执行 `adb devices`。若出现 IP 设备 ID 与 `_adb-tls-connect._tcp` 别名同时在线，它们可能是同一手机；所有命令仍必须显式使用用户确认的设备 ID：`adb -s DEVICE_ID ...`。

开始前输出并保存：设备 ID、型号、Android 版本、屏幕分辨率、高德包名。检测多个物理设备时不得自行选择。无线断开时尝试按已知 IP:端口重连；失败则保存进度并停止手机操作。

若高德明显卡顿、页面状态混乱或连续两次响应异常，可以强制停止并重新启动高德，再从当前站点重新进入。重启前先保存 checkpoint。

### 3.2 定位优先级

优先 UI hierarchy / uiautomator2 的 text、content-desc、resource-id 和 bounds；其次 ADB UI dump；只有自定义 Canvas/图表读不到时才使用截图 OCR/视觉。坐标点击只能基于当前已识别元素 bounds 或稳定的相对位置，禁止用一套固定坐标跑全程。

### 3.3 单站状态机

每个场站严格执行以下状态，不跨状态盲点：

1. `SEARCHED`：用去重名单的完整场站名搜索；可用 POI deep link 时优先用 POI ID进入。
2. `RESULT_VERIFIED`：核对搜索结果的标题和地址/POI ID，确认是目标场站。
3. `DETAIL_TOP`：进入详情页，核对页面标题与目标场站名；保存顶部截图、XML 和原始文本。
4. `EQUIPMENT_CAPTURED`：找到“电站信息”，保存所有设备卡片。解析 `空闲11/12` 时枪数量取 12；功率取 `120.0kW` 的 120。多种功率/类型分别记录，不能合并。
5. `PRICE_ENTRY_FOUND` 或 `NO_PRICE_ENTRY`：价格通常在“电站信息”下方。入口可能是“24小时价格趋势图/柱状图”，也可能只显示 `￥1.16/度` 和“查看”。两种都算价格入口。
6. `PRICE_DETAIL_CAPTURED`：点击 **价格数字、价格柱状图或其明确的价格入口**，不是停车费“查看详情”、价格说明、评价、照片或广告。只有出现“充电价格详情/充电费/充电时段/参考价/充电站价/电费/服务费”等熟悉结构后，才保存价格详情。
7. `SAVED`：写入 meta/checkpoint，随后返回并处理下一站。

任何阶段看不到预期界面：保存当前截图、XML、文本和错误原因，然后返回。不要试探性乱点。单站失败不能终止批次。

### 3.4 截图必须完整

每个场站至少保存：搜索或进入证据、详情顶部、电站信息区域。凡出现价格入口，必须另外保存价格详情。

价格详情页面：

- 先截进入后的首屏，并同时保存 UI dump/文本；
- 若价格表超出屏幕，在确认仍处于价格详情弹层/页面后，只在价格列表区域内滚动，每次滚动后再截图和 dump；
- 通过已见时段集合去重，连续滚动后无新时段或到页面底部才结束；
- 有“快充/超充/慢充”等页签时逐个切换并分别截图，元数据记录 tariff type；
- 全天统一价也必须进入详情并截图。页面只显示总价时，电费和服务费留空；禁止倒算；
- 即使详情只显示部分时间（例如 `06:00-14:59`、`14:59-23:59`），也视为有效证据并转换，不能因为没有 `00:00-06:00` 就把整站价格留空；
- 价格截图文件必须能追溯到场站 POI ID、设备类型和采集时间。

建议目录：

```text
captures/
  0509_场站名称_POIID/
    meta.json
    01_search.png/.xml/.txt
    02_detail_top.png/.xml/.txt
    03_equipment_1.png/.xml/.txt
    05_price_fast_1.png/.xml/.txt
    05_price_fast_2.png/.xml/.txt
    06_price_slow_1.png/.xml/.txt
```

`meta.json` 至少包含 index、poi_id、station_name、operator、target_distances、device_id、status、screenshots、equipment groups、price entry type、失败原因和完成时间。写临时文件后原子替换，避免中断损坏。

## 4. 阶段 C：截图解析

离线统一解析，禁止边点手机边直接写最终 Excel。

### 4.1 设备信息

- 从详情页“电站信息”读取类型、功率和总枪数；`空闲 x/y` 只取 y。
- 同一站存在 `600kW 8枪` 与 `120kW 12枪` 时建立两组设备。
- 若截图无法明确判断设备类型与某价格页的对应关系，不要把同一价格复制到所有功率组，列入冲突清单。

### 4.2 价格信息

每个截图中出现的每个时段均生成记录：`start_time`、`end_time`、`total_price`、`electricity_fee`、`service_fee`。

- 保留高德显示的边界，例如 `14:59` 和 `23:59`，不要擅自改为 `15:00` 或 `24:00`；
- 不要求价格覆盖完整 24 小时；截图能确认几段就录几段；
- 同一时段多张截图完全一致时去重；数值冲突时不自动覆盖，进入复核清单；
- 已有表中存在的时段保持不动，只补截图确认但表中缺失的时段；
- 不允许把补录时段集中追加到 Sheet 底部。必须重新构建对应场站组，并按开始时间排列在原场站下；
- 总价、电费、服务费均以页面显示为准。缺失项为空；可用 `总价≈电费+服务费` 做异常检查，但不能用它生成缺失值。

## 5. 证据到表格的强制复核

生成 Excel 前做两次集合核对：

1. **价格证据反查**：所有包含价格表头和至少一个有效时段的价格截图，必须在解析结果中有对应记录。
2. **表格反查**：表格中的每条价格必须能定位到站点目录和价格截图；不得来源于列表当前价、趋势图标签猜测或导航页。

重点输出以下队列：

- `price_screenshot_but_no_rows`：有价格详情截图，表内一条价格都没有；必须修复；
- `price_period_missing`：截图有某时段但表内缺失；必须补入；
- `price_conflict`：同一站/类型/时段截图数值冲突；人工复核，不自动选值；
- `price_entry_not_opened`：详情页存在价格入口但没有价格详情截图；需要回到手机补采；
- `equipment_tariff_unmapped`：多设备类型与价格页无法对应；不得复制价格；
- `no_price_entry`：详情页确实未显示价格入口；保留空值及证据，不算遗漏。

复核不能用“是否覆盖 00:00-23:59”决定是否录入。全天完整性只能作为数据质量提示，不能阻止部分时段入表。

## 6. 最终 Excel

每个原始目标建立一个 Sheet，名称遵守 Excel 31 字符和非法字符限制，发生修改时记录映射。字段顺序固定：

`目标名称 | 场站名称 | 运营商 | 距离 | 充电功率(kW) | 枪数量 | 开始时间 | 结束时间 | 总价(元/度) | 电费(元/度) | 服务费(元/度)`

数据组织：

- 按目标输入顺序建 Sheet；Sheet 内按 API 距离排序，保持同一场站相邻；
- 一个设备组 × 一个可确认价格时段 = 一行；多个功率和多个时段做有证据的组合，不得无依据笛卡尔复制；
- 同一场站同一设备组的 A-F 列在最终展示版纵向合并，G-K 每个时段独立；没有价格时仍保留一行，价格列为空；
- 距离使用 3 公里候选表中“目标点 → 场站”的距离并保留原显示单位，不使用详情页驾车距离；
- 运营商优先取页面明确字段；仅当名称可明确识别品牌时提取，否则留空；
- 从完整数据集重新生成工作簿。不要在旧工作簿底部批量累加补录行；
- 每完成一批即保存中间 JSON/CSV 和检查点，最终再一次性生成 Excel。

## 7. 完成验收

完成前必须验证：

- API 查询半径均为 3000 米，分页完整；
- 排除项中无蔚来、卡车专用、两轮车/车行、内部专用、泛称无后缀点位；
- 去重采集名单与目标距离映射可回填；
- 每个已处理站点有标题核验证据和详情截图；
- 每个出现价格入口的站点有价格详情截图，或明确列在 `price_entry_not_opened`；
- 所有价格详情截图中的可见时段均已转换，不论是否全天；
- 表内没有把空闲枪数当总枪数，没有合并不同功率；
- 新补价格与场站相邻，未堆在 Sheet 底部；
- 抽查首站、中间站、末站，以及“统一价、部分时段、多设备、多页价格”各至少一例；
- 输出未解决冲突及失败清单，不用猜测填满。

给用户汇报：目标数、API 候选数、筛选后数、去重站数、成功详情数、有价格入口数、价格详情截图数、已转换价格时段数、无价格入口数、需补采数、冲突数和最终文件路径。
